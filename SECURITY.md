# Security Policy

This is the organization-wide fallback for repositories that do not have their own `SECURITY.md`. Always follow the affected repository's policy when one exists; its reporting channel, scope, supported versions, and response targets take precedence. Cordite, Unshelv'd, and Vetviona have repository-specific security instructions.

## Reporting a vulnerability

**Do not report security vulnerabilities through public issues, discussions, or pull requests.**

For a repository without its own policy, use GitHub's **Report a vulnerability** option on its Security tab when available. If no private reporting option is available, use the contact link on the [official KoshkiKode website](https://koshkikode.com) to request a private reporting channel. Do not include vulnerability details in a public form or issue.

Include the affected repository and component, a description of the potential impact, and safe reproduction details. Do not access, modify, or disclose data that is not yours.

## Scope and response

Report suspected security issues in KoshkiKode-maintained code that could affect confidentiality, integrity, or availability. The affected project's own policy determines its precise scope and version support. There is no organization-wide response or patch timeline; please allow maintainers a reasonable opportunity to assess and address a report before public disclosure.
